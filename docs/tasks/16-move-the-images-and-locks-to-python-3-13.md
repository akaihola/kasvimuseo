# 16. Move the images and the locks to Python 3.13

This task helps release maintainers validate every release on the interpreter that production will run.

- Priority: High.
- Owner: Release maintainer.

## Work

1. Change the base image of `Dockerfile` and `dev/Containerfile` from `python:3.12.12` to the current `python:3.13` Alpine image.
2. Re-resolve `requirements/production.txt`, `requirements/dev.txt` and `requirements/testing.txt` under Python 3.13 with the same `pip-compile` command their headers record.
3. Build both images and confirm that their installed packages match the committed locks.
4. Run the application suite, the coverage gate, the browser checks and the production image check.
5. Record the commands and the results in issue 088, "Results", with the date.

## Evidence

The deployment repository selects Debian 13 and Python 3.13 for production since 2026-10-07.
Its rehearsal of 2026-10-07 installed the Django 6.0.7 candidate on Python 3.13.5 and passed the deployment checks there.
The public images still build on `python:3.12.12-alpine3.22`, and the three locks say `autogenerated by pip-compile with Python 3.12`.
The suite has never run on Python 3.13, so a release validated here runs on a different interpreter than production.

## Completion checks

- [ ] Both images build on Python 3.13 and match their locks.
- [ ] The application suite, the coverage gate, the browser checks and the production image check pass on Python 3.13.
- [ ] Issue 088 records the Python 3.13 results.
